# МГКАП — десктопная версия на Rust

Кроссплатформенный клиент расписания колледжа: **Windows, Linux, macOS**.
Ядро (загрузка PDF, парсинг, звонки, аналитика) вынесено в `pulse-core` и покрыто
тестами; интерфейс — `pulse-app` на [`egui`/`eframe`](https://github.com/emilk/egui).

Почему Rust и как это соотносится с Android-версией — в
[`../docs/PULSE_DESKTOP_RUST.md`](../docs/PULSE_DESKTOP_RUST.md).

## Сборка и запуск

Нужен Rust 1.85+ (проверено на 1.100) и системные библиотеки для оконного ввода:

```bash
# Linux (Debian/Ubuntu): оконный ввод и OpenGL
sudo apt install build-essential pkg-config libxkbcommon-dev libwayland-dev \
                 libx11-dev libxcursor-dev libxi-dev libxrandr-dev libgl1-mesa-dev
```

```bash
cd pulse-desktop
cargo run -p pulse-app                  # отладочная сборка
cargo build --release -p pulse-app      # бинарник: target/release/pulse-app
cargo test --workspace                  # 68 тестов ядра + 10 тестов интерфейса
```

На Windows и macOS ничего дополнительно ставить не нужно: `eframe` тянет
winit/glow, а системный шрифт для кириллицы подхватывается автоматически.

### Готовые сборки: Windows и macOS

| Платформа | Как собирается | Результат |
|---|---|---|
| Windows x86_64 | `cargo zigbuild --release -p pulse-app --target x86_64-pc-windows-gnu` | `pulse-app.exe` (PE32+, GUI-подсистема, без консольного окна) |
| Linux x86_64 | `cargo build --release -p pulse-app` | `pulse-app` |
| macOS x86_64 и arm64 | CI `.github/workflows/release.yml` на `macos-15` | `МГКАП.app` → `.zip` и `.dmg`, плюс универсальный бинарник (`lipo`) |

Windows кросс-компилируется с Linux: `zig` подменяет mingw-линкер, отдельный
`mingw-w64` не нужен.

```bash
rustup target add x86_64-pc-windows-gnu
cargo install cargo-zigbuild            # один раз
# zig распакован в ~/.local/opt, симлинк — ~/.local/bin/zig
cargo zigbuild --release -p pulse-app --target x86_64-pc-windows-gnu
```

macOS с Linux собрать нельзя — нужен SDK Apple, поэтому `.app` и `.dmg`
собирает GitHub Actions:

```bash
gh workflow run "Сборка приложений"
gh run list --workflow=release.yml --limit 1
gh run download <run-id>                # артефакты в текущий каталог
```

Готовые файлы для раздачи лежат в `dist/` — по папке на систему, в каждой свой
`README.md` с инструкцией по установке и `SHA256SUMS.txt`:

| Папка | Содержимое |
|---|---|
| `dist/windows/` | `mgkap.exe` (статический CRT, без Visual C++ Redistributable) |
| `dist/macos/` | `mgkap-macos-universal.{dmg,zip}` — один файл на любой Mac, плюс сборки под arm64 и Intel |
| `dist/linux/` | `mgkap` — локальная release-сборка |

Сам каталог `dist` в `.gitignore`: бинарники в репозиторий не попадают.

Сборка macOS подписана ad-hoc (`codesign --sign -`): на Apple Silicon
неподписанный бинарник не запускается вовсе. Нотаризации Apple нет, поэтому
при первом запуске Gatekeeper скажет «неизвестный разработчик» — открывать
через правый клик → «Открыть», либо один раз снять карантин:

```bash
xattr -dr com.apple.quarantine /Applications/МГКАП.app
```

### Иконки и шрифты

Иконки в интерфейсе — обычные символы Unicode. Встроенный в `egui` шрифт
Ubuntu-Light эмодзи не содержит, поэтому включена фича `egui/monochrome_emoji_fonts`:
в сборку попадают NotoEmoji и emoji-icon-font, и иконки рисуются одинаково
на всех трёх ОС. Символы, которых нет ни в одном из этих шрифтов, заменены
на похожие по смыслу (например, пробирка 🧪 → атом ⚛).

Проверяется тестом `every_used_icon_has_a_glyph`: он рендерит все иконки
приложения с политикой `MissingGlyphPolicy::Panic`, поэтому новый символ без
глифа уронит `cargo test`, а не превратится в «квадратик» у пользователя.

### Скриншоты вкладок без окна

```bash
cargo test -p pulse-app --features shots render_tabs_to_png -- --ignored --nocapture
```

Кладёт PNG в `/tmp/pulse-shots` (тёмная и светлая темы, неделя, диалог, редактор
звонков). Фича `shots` тянет wgpu, поэтому по умолчанию не собирается.

## Где лежат данные

Один каталог, JSON-файлы с теми же именами полей, что в Android-версии:

| ОС | Каталог |
|---|---|
| Linux | `~/.local/share/pulse` |
| macOS | `~/Library/Application Support/by.Pulse.pulse` |
| Windows | `%APPDATA%\Pulse\pulse\data` |

Файлы: `settings.json`, `schedule.json`, `teachers.json`, `homework.json`,
`performance.json`, `bells.json`, `last_raw_text.txt`. Путь всегда виден
в строке состояния и в «Настройки → Данные».

Переносимый режим (флешка, тесты, второй профиль):

```bash
PULSE_DATA_DIR=/путь/к/каталогу cargo run -p pulse-app
```

## Что умеет

Интерфейс подстраивается под роль: переключатель «Студент / Преподаватель»
стоит в шапке, выбранная роль сохраняется в `settings.json`.

| Роль | Вкладки |
|---|---|
| Студент | Расписание, Преподаватели, Успеваемость, Домашние задания, Уведомления, Настройки |
| Преподаватель | Расписание (моё), Группы, Преподаватели, Настройки |

| Вкладка | Возможности |
|---|---|
| Расписание | День/неделя, навигация по датам, блок «сейчас и далее», замены и переносы из последнего обновления, звонки дня, подсветка текущей пары; у преподавателя — только свои пары |
| Группы | Только у преподавателя: список всех групп из PDF, пары выбранной группы по дням и на неделю |
| Преподаватели | Справочник из расписания, поиск по фамилии/предмету/кабинету, личное расписание по дням, недельный вид |
| Успеваемость | Семестры, предметы, оценки и КР, средний балл, стипендия, распределение, риски, тренды, рекомендации, симуляция «что будет, если» |
| Домашние задания | CRUD, сроки, «осталось пар», напоминание накануне, группы «просрочено / сегодня / далее» |
| Уведомления | Сводка внутри окна: просроченные ДЗ, сроки, пары на сегодня и завтра, изменения расписания, долги, предметы без оценок |
| Настройки | Роль, имя и группа (или своё имя из справочника), тёмная/светлая тема, 10 акцентных цветов, режим округления, автообновление, редактор звонков, сокращённые дни, сброс данных |

Мелочи, которые экономят клики: у вкладок подсказки и счётчики (активные
задания, уведомления, число групп и преподавателей), `Ctrl+1…6` переключает
вкладки текущей роли, высота окна и ширина списка подобраны под 1200×800.

Название приложения — «МГКАП»: слово `Pulse` в интерфейсе не встречается
(окно, шапка, «О программе»). Имена крейтов, файлов и каталог данных `pulse`
не переименовывались — это внутренняя кухня и совместимость с сохранёнными
данными.

Обновление расписания — кнопка «⟳ Обновить»: приложение скачивает страницу с
сайта колледжа, находит PDF, извлекает текст и разбирает пары. Всё в фоновом
потоке, интерфейс не блокируется.

Расписание обновляется и само: при первом запуске (когда текста ещё нет) и при
любом следующем запуске, если данные старше 6 часов. Время последней загрузки
лежит в `settings.json` (`lastFetchAt`) и видно в настройках строкой
«Последнее обновление». Галочка в настройках отключает автообновление целиком.
Скачанное сразу пишется на диск (`last_raw_text.txt`, `schedule.json`), так что
после перезапуска расписание открывается мгновенно и без сети.

Анимации — короткие и служебные: содержимое вкладки проявляется за 180 мс,
бейдж «сейчас» мягко пульсирует, полоски распределения оценок доезжают до
значения, строка статуса внизу появляется и гаснет. В тестах и при съёмке
скриншотов анимации выключены, поэтому кадр детерминирован.

«Моё расписание» преподавателя строится по имени из настроек и хранится в
отдельном кэше: выбор любого преподавателя в справочнике показывает его пары,
но свои не подменяет.

**Замены и переносы.** Отдельного файла замен сайт колледжа не публикует: на
странице «Замены в расписании» лежит новый PDF расписания, где замены уже
внесены, а пометок в тексте нет — это проверено на текущем файле. Поэтому
приложение сравнивает прошлую и новую версии расписания (`pulse_core::changes`)
и показывает результат карточкой «Замены и переносы» на вкладке «Расписание»:

| Метка | Что значит |
|---|---|
| замена | на той же паре другой предмет, преподаватель или кабинет |
| перенос | та же пара переехала на другое время или в другой кабинет |
| снята | пары больше нет в новой версии |
| добавлена | пары не было в прошлой версии |

Сравниваются только дни, которые есть в обеих версиях: когда колледж выложит
расписание на следующую неделю, все её дни иначе выглядели бы как «всё снято и
всё добавлено». Найденные изменения лежат в `schedule_changes.json`, живут 21
день и убираются кнопкой «✕» (или полностью — сбросом данных). У преподавателя
сравниваются его собственные пары, у студента — пары активной группы.

## Ограничения (осознанные)

1. **Системных уведомлений ОС нет.** Вкладка «Уведомления» — внутренний центр
   напоминаний: сводка собирается при открытии, пока приложение запущено.
   Планировщик задач ОС и трей не реализованы.
2. **Нужна сеть для обновления расписания.** Офлайн приложение работает на
   кэше `last_raw_text.txt` и `schedule.json`.
3. **Нет NFC/QR-обмена, виджетов и Wear OS** — это мобильные особенности,
   десктопного аналога у них нет.
4. **Разбор PDF зависит от структуры файла.** Если сайт поменяет вёрстку или
   отдаст скан без текстового слоя, парсер не найдёт пары — причина будет
   видна в журнале загрузки (stderr) и в строке состояния.

## Структура

```
pulse-desktop/
├── Cargo.toml                 # workspace: pulse-core + pulse-app
└── crates/
    ├── pulse-core/            # логика без GUI, 68 тестов
    │   └── src/
    │       ├── model.rs       # LessonPair, Teacher, кэш расписания
    │       ├── parser.rs      # разбор текста расписания, группы, преподаватели
    │       ├── bells.rs       # звонки: обычный/понедельник/четверг/суббота/сокращённый
    │       ├── source.rs      # страница колледжа → PDF → текст
    │       ├── homework.rs    # домашние задания, «осталось пар»
    │       ├── performance.rs # предметы, семестры, округление, средние
    │       ├── analytics.rs   # стипендия, риски, тренды, симуляция
    │       ├── subject_theme.rs # эмодзи и цвет по названию предмета
    │       ├── datetime.rs    # разбор и «человеческое» форматирование дат
    │       └── storage.rs     # атомарная запись JSON в каталог данных
    └── pulse-app/             # egui/eframe
        └── src/
            ├── main.rs        # окно 1200×800, минимум 960×620
            ├── app.rs         # состояние, вкладки по роли, фоновое обновление, окна
            ├── store.rs       # настройки (включая роль) и файлы
            ├── theme.rs       # палитра, шрифты
            └── views/         # по модулю на вкладку + общие элементы
```

Тесты интерфейса (`pulse-app`) считают раскладку без окна через
`egui::Context::run_ui`: каждая вкладка обеих ролей, пустое состояние,
открытые диалоги и сброс данных проверяются обычным `cargo test`. Отдельные
тесты проверяют, что у каждой иконки есть глиф в подключённых шрифтах, и что
переключение роли меняет набор вкладок и сохраняется в `settings.json`.
