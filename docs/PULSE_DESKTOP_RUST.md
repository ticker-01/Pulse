# Pulse → Desktop на Rust (Windows / Linux / macOS)

Документ подготовлен на основе анализа текущего репозитория **МГКАП (Pulse)** (Android, Kotlin/Jetpack Compose, версия 1.3.5, `com.example.pulse`).  
Цель: ответить, можно ли реализовать аналогичное приложение на **Rust** для Windows, Linux и macOS, и предложить практическую архитектуру.

## 1. Что делает текущее приложение (факты по проекту)

- **Расписание замен**: загрузка HTML/PDF с сайта колледжа, извлечение текста (PDFBox), парсинг пар/групп/преподавателей, кэш в локальном хранилище (`SharedPreferences` + JSON, `schedule_history`).
- **UI/экраны**: расписание (день/неделя, текущая пара), преподаватели, успеваемость (семестры, оценки, аналитика/прогноз), домашние задания, уведомления, настройки, онбординг.
- **Домашние задания**: CRUD, сроки, привязка к парам, отметка выполнения.
- **Успеваемость**: семестры/предметы/оценки (в т.ч. КР), средний балл, аналитика (`PerformanceAnalytics`), симуляция.
- **Обмен/интеграции (мобильные)**: NFC/HCE, QR, шаринг изображений расписания, виджеты (Glance), напоминания/будильники, foreground/live-уведомления, Wear OS (заготовка).
- **Фон**: периодическая проверка PDF/ДЗ (WorkManager), точные будильники (AlarmManager).
- **Хранение**: без БД и без собственного бэкенда, кроме скачивания PDF; локальные JSON-структуры.

Вывод: ядро продукта — **сеть → PDF/текст → парсинг → модели расписания/ДЗ/оценок → локальное хранение → UI и напоминания**. Это переносимо на десктоп; часть Android-специфики требует замены.

## 2. Возможно ли такое же приложение на Rust для Windows, Linux и macOS?

**Да.** Rust подходит для кроссплатформенного десктопа: единая кодовая база для бизнес-логики и (при выборе подходящего UI-стека) для интерфейса. Нативная производительность, безопасность памяти и хорошая экосистема для HTTP, парсинга, сериализации и асинхронности упрощают перенос ядра.

Полный «1:1» со всеми мобильными возможностями недостижим из-за платформенных различий (виджеты ОС, NFC/HCE, точные будильники/фон в спящем режиме), но **функциональный аналог** для десктопа реализуем.

## 3. Соответствие функций Android → Desktop (Rust)

| Функция Pulse | Переносимость | Вариант на Rust / десктопе |
|---|---|---|
| Загрузка PDF/страниц, парсинг расписания | Высокая | `reqwest` (HTTP), `scraper`/`lol_html` (HTML), `pdf-extract`/`lopdf` или binding к PDFium (`pdfium-render`) для текста; regex/парсер на `regex` + своя логика (порт правил из `ScheduleViewModel`) |
| Модели, кэш, история | Высокая | `serde`, `serde_json`, файлы в app-data или `rusqlite`/`sled` для надёжного хранения |
| UI (расписание, ДЗ, успеваемость, настройки) | Высокая | `iced`, `egui` (`eframe`), `Slint`, `Dioxus`, либо `Tauri` (Rust backend + web UI). Для «нативного Rust UI» часто выбирают `iced`/`egui`/`Slint` |
| Локальные уведомления | Средняя/высокая | `notify-rust` (Linux/macOS/Windows), системный трей/бейджи через `tray-icon` + `muda` |
| Фоновая проверка обновлений PDF | Средняя | Фоновая задача в процессе + планировщик ОС (cron/Task Scheduler/launchd) или проверка при запуске/по таймеру, пока приложение/агент запущен |
| Напоминания о парах / «будильник» | Средняя | Уведомления по таймеру при работающем приложении/трей-агенте; интеграция с системным календарём (`.ics`) как надёжная альтернатива точным alarm’ам Android |
| Виджеты рабочего стола/домашнего экрана | Низкая/платформенная | На десктопе обычно **системный трей + мини-окно/поповер**; нативные виджеты ОС требуют отдельных платформенных реализаций (Win11 widgets, macOS widgets, Linux — зависит от DE) |
| NFC/HCE обмен картой | Низкая на десктопе | Заменить на **QR-код, файл экспорта, ссылку/буфер обмена**; NFC на ПК редок и требует спец. API/железа |
| Генерация/шаринг картинки расписания | Высокая | Рендер в изображение (`tiny-skia`, `image`, `resvg` и т.п.), сохранение/«Поделиться» через системный диалог |
| Wear OS / live foreground service | Низкая | Не применимо; аналог — трей-статус и уведомления |

## 4. Рекомендуемый стек (pure Rust-ориентированный)

- **Язык/сборка**: Rust stable, Cargo workspace.
- **UI**: `iced` (Elm-подобная архитектура, кроссплатформенно) или `eframe/egui` (быстрый императивный UI). Для близости к «современному» виду — `Slint`.
- **Асинхронность/сеть**: `tokio`, `reqwest`.
- **Сериализация/конфиг**: `serde`, `serde_json`, `toml`/`directories` (пути app-data).
- **Хранение**: `rusqlite` (надёжнее JSON для истории/запросов) или JSON-файлы как в оригинале для простоты миграции логики.
- **Парсинг**: `regex`, `scraper`, PDF-библиотека по результатам тестов на реальных файлах колледжа (качество извлечения текста критично).
- **Уведомления/трей**: `notify-rust`, `tray-icon`.
- **Логи/ошибки**: `tracing`, `anyhow`/`thiserror`.
- **Планировщик внутри приложения**: `tokio::time` / `clokwerk` (пока процесс активен).

Альтернатива: **Tauri** — UI на web-технологиях, логика и доступ к ОС на Rust; проще получить сложную вёрстку, но часть «на Rust» уходит во frontend.

## 5. Предлагаемая структура проекта

```text
pulse-desktop/
  Cargo.toml                # workspace
  crates/
    pulse-core/             # платформенно-независимая логика
      src/
        lib.rs
        model.rs            # LessonPair, HomeworkItem, SubjectGrade, ...
        schedule/
          mod.rs
          fetch.rs          # поиск ссылок, скачивание PDF
          pdf_text.rs       # извлечение текста
          parse.rs          # порт правил парсинга групп/пар
        homework.rs
        performance.rs
        storage.rs          # трейты/реализация хранилища
        analytics.rs
    pulse-app/              # GUI + интеграции ОС
      src/
        main.rs
        app.rs              # состояние UI, экраны
        views/
        notifications.rs
        tray.rs
```

Принцип: максимум логики в `pulse-core` (тестируемо, переиспользуемо), минимум платформенного кода в `pulse-app`.

### 6.2 Модели (порт ключевых сущностей)

```rust
// crates/pulse-core/src/model.rs
use chrono::NaiveDate;
use serde::{Deserialize, Serialize};

#[derive(Debug, Clone, Serialize, Deserialize, PartialEq, Eq)]
pub struct LessonPair {
    pub pair_number: u8,
    pub start: String,      // "08:30" — как в исходных данных, с парсингом отдельно
    pub end: String,        // "10:05"
    pub subject: String,
    pub room: String,
    pub teacher: String,
    pub group: String,
}

#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct HomeworkItem {
    pub id: String,
    pub subject: String,
    pub task: String,
    pub due_date: Option<NaiveDate>,
    pub is_completed: bool,
    pub notify_day_before: bool,
    pub target_pairs: Option<u32>,
}

#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct SubjectGrade {
    pub subject: String,
    pub teacher: Option<String>,
    pub grades: Vec<i32>,
    pub kr_grades: Vec<i32>,
    pub target: Option<f32>,
}
```

### 6.3 Интерфейс получения расписания (идея)

```rust
// crates/pulse-core/src/schedule/mod.rs
use anyhow::Result;
use chrono::NaiveDate;
use std::collections::BTreeMap;
use crate::model::LessonPair;

#[derive(Debug, Clone)]
pub struct ScheduleSnapshot {
    pub by_date: BTreeMap<NaiveDate, Vec<LessonPair>>,
    pub source_urls: Vec<String>,
}

pub trait ScheduleSource {
    async fn fetch_snapshot(&self, group: &str) -> Result<ScheduleSnapshot>;
}
```

### 6.4 Точка входа GUI (условный пример на `eframe`)

```rust
// crates/pulse-app/src/main.rs (эскиз)
fn main() -> eframe::Result<()> {
    let options = eframe::NativeOptions::default();
    eframe::run_native(
        "МГКАП Pulse",
        options,
        Box::new(|_cc| Ok(Box::new(PulseApp::default()))),
    )
}

#[derive(Default)]
struct PulseApp {
    selected_group: String,
    // состояние экранов: расписание, ДЗ, успеваемость...
}

impl eframe::App for PulseApp {
    fn update(&mut self, ctx: &egui::Context, _frame: &mut eframe::Frame) {
        egui::CentralPanel::default().show(ctx, |ui| {
            ui.heading("Расписание");
            ui.label("Кроссплатформенный клиент на Rust (Windows/Linux/macOS)");
            // далее: вкладки, список пар, загрузка, кэш
        });
    }
}
```

(Для реального проекта вместо эскиза выбирается один UI-фреймворк и реализуются экраны/навигация.
Эскиз написан под старый API `egui`: в 0.37 у `eframe::App` больше нет `update`, кадр
приходит в `fn ui(&mut self, ui: &mut egui::Ui, frame: &mut eframe::Frame)`, а
`TopBottomPanel`/`SidePanel` объединены в `egui::Panel`.)

## 7. Сложности и ограничения при переносе

1. **Парсинг PDF**: в Android используется PDFBox; на Rust качество извлечения текста зависит от библиотеки и структуры конкретных PDF — нужен ранний прототип парсера на реальных файлах.
2. **Фон и точность таймеров**: десктоп-приложение, не работающее в фоне/трее, не заменит `AlarmManager`/WorkManager; нужен агент в трее или системные средства планирования.
3. **NFC/HCE**: прямого аналога нет — перенос через QR/экспорт.
4. **Виджеты**: платформенно-специфичны; базовый кроссплатформенный аналог — трей-меню и быстрый просмотр.
5. **Динамические темы Material You**: на десктопе заменить на системную/светлую/тёмную тему и акцентные цвета.
6. **Хранилище**: при желании совместимости можно повторить JSON-схемы; для роста объёма данных предпочтительнее SQLite.

## 8. Итог

- **Да**, приложение, аналогичное Pulse по основным сценариям (расписание из PDF, домашние задания, успеваемость, уведомления, кроссплатформенный UI), **можно реализовать на Rust для Windows, Linux и macOS**.
- Практичный путь: вынести общее ядро (модели, загрузка, парсинг, аналитика, хранение) в `pulse-core`, UI и ОС-интеграции — в `pulse-app` на `iced`/`egui`/`Slint` (или Tauri), а мобильные-only функции заменить десктопными аналогами (трей, QR/экспорт, системные уведомления).
- Реалистичный объём: сначала MVP (загрузка+парсинг+расписание+кэш+настройки), затем ДЗ, успеваемость/аналитика, уведомления и трей.

## 9. Статус реализации

Вариант из раздела 5 уже реализован в каталоге [`../pulse-desktop`](../pulse-desktop/README.md):
workspace `pulse-core` (логика, 60 тестов) + `pulse-app` (`eframe`/`egui` 0.37, 5 тестов
раскладки без окна). Что сделано по пунктам плана:

| Пункт плана | Состояние |
|---|---|
| Загрузка PDF с сайта и разбор текста | готово (`pulse-core::source` + `parser`), проверено на реальной странице колледжа |
| Расписание: день/неделя, «сейчас идёт», звонки | готово |
| Преподаватели: справочник и личное расписание | готово, плюс недельный вид |
| Режим преподавателя | готово: переключатель роли, «Моё расписание», вкладка «Группы» |
| Домашние задания: CRUD, сроки, «осталось пар» | готово |
| Успеваемость: семестры, оценки, КР, аналитика, симуляция | готово (`performance` + `analytics`) |
| Хранение в каталоге данных ОС, JSON с полями Android-версии | готово (`storage`) |
| Уведомления | только внутренний центр напоминаний; системных уведомлений ОС нет |
| Трей, работа в фоне, планировщик | не реализовано (осознанно: см. ограничения в README) |
| Обмен (QR/NFC), виджеты, Wear OS | не переносится на десктоп |
| Сборки под Windows и macOS | `.exe` собирается локально через `cargo zigbuild`; `.app`/`.dmg` — CI на `macos-14` (x86_64 + arm64) |

Заметки по ходу реализации:

- **Брендинг.** В интерфейсе приложение называется «МГКАП»: заголовок окна, шапка,
  раздел «О программе». Слово `Pulse` из видимых текстов убрано, а имена крейтов,
  файлов и каталог данных `pulse` оставлены — от них зависит совместимость с уже
  сохранёнными данными и командой `PULSE_DATA_DIR`.
- **Режим преподавателя.** Роль лежит в `settings.json` (`role: student|teacher`),
  старые файлы без этого поля читаются как «студент». Набор вкладок задаёт
  `Tab::for_role`: у студента — расписание, преподаватели, успеваемость, задания,
  уведомления, настройки; у преподавателя — своё расписание, группы, справочник,
  настройки. Расписание чужой группы кэшируется отдельно (`group_view_*`), чтобы
  не подменять группу студента.

- **Иконки и шрифты.** Встроенные шрифты `egui` (Ubuntu-Light + egui-icons) не содержат
  эмодзи, поэтому в `pulse-app` включена фича `egui/monochrome_emoji_fonts`: в сборку
  попадают NotoEmoji и emoji-icon-font, и один и тот же набор иконок рисуется на
  Windows, Linux и macOS. Символы, отсутствующие во всех трёх шрифтах (🧪, 🧬, 🦺, 🏛, 🏗,
  🤖, 🧰, 🤝), заменены на близкие по смыслу: ⚛, 🌱, 🚧, 📜, 🔗, 🕹, 🔧, 💬.
  Тест `every_used_icon_has_a_glyph` рендерит все иконки с
  `MissingGlyphPolicy::Panic`, так что символ без глифа ломает `cargo test`.
- **Доступность.** Проверка `egui_kittest` (её пришлось прогонять при отладке раскладки)
  требовала имя у каждого интерактивного элемента: выпадающим спискам добавлен
  `labelled_by`, полям звонков — подсказки, флажку задания — имя предмета. Это же
  делает интерфейс пригодным для скринридеров.
- **Сознательные отклонения от Android** перечислены в шапке соответствующего модуля:
  `build_deep_report` подключает риски и рекомендации, `subject_theme` распознаёт
  «Физическая культура» и отдельный токен «ИТ», цвет аватара преподавателя
  детерминирован из имени.
